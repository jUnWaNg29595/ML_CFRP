# 虚拟分子筛选模型驱动设计

**日期：** 2026-08-22  
**状态：** 待用户审阅  
**范围：** 虚拟分子筛选页面及其分子设计后端

## 1. 背景与目标

当前页面中的“模型引导”主要把模型效应转换成标签，候选分子仍以随机抽样或预置 SMILES 为主；树脂与固化剂组合也只是使用点号拼接，没有明确的原子位点、化学键类型和价态约束。

本次改造目标：

- 以训练数据中已验证的分子为骨架，生成可追溯的局部结构变体；
- 同时支持规则骨架编辑、Reaction SMARTS 模板和模型引导的受限图搜索；
- 对每次连接执行明确的位点、键级、价态、元素、环和官能团校验；
- 将合法候选送入现有分子特征 workflow、模型预测、适用域和结构合理性过滤；
- 保存父子结构、编辑规则、位点和模型评分，保证结果可解释、可复现；
- 移除旧的直接候选库/随机候选流程，页面只保留新的分子设计引擎。

## 2. 设计决策

### 2.1 三种设计模式

首版同时实现三条路线：

1. **A：骨架编辑。** 从训练数据、当前数据中的有效结构或用户上传的候选中选择骨架，执行角色专用局部编辑。
2. **B：Reaction SMARTS 模板。** 用版本化模板声明输入角色、位点要求、反应 SMARTS、键变化、产物限制和风险等级。
3. **C：模型引导受限图搜索。** 从 A/B 的合法产物继续扩展，使用 beam search 根据模型预测、适用域、不确定度、可合成性和多样性保留候选。C 首版不依赖新的生成模型；未来可替换生成器，不改变化学校验和评分接口。

树脂和固化剂始终分别设计。最终配方可以把两条分子 SMILES 作为两个输入列组合，但不把配方混合物错误地当作一个共价连接产物。

### 2.2 默认编辑范围

四类编辑默认全部启用，并可分别关闭和限额：

- 芳环氢取代：甲基、卤素、甲氧基、羟基等小取代基；
- 羟基/胺基官能化：缩水甘油醚、烷基、醚链等角色允许的取代；
- 链段长度扫描：对已有烷基或醚链执行 C1-C6 长度变化；
- 树脂/固化剂角色专用变换：树脂保持环氧角色约束，固化剂保持活性位点约束。

每类编辑都保留原始骨架作为锚点，默认不允许无父结构的新分子。

## 3. 系统架构

新增 `core/molecule_design.py`，不继续把化学编辑逻辑堆进页面函数或现有筛选模块。核心组件：

- `ScaffoldMiner`：读取训练/候选数据，规范化 SMILES，去重，保留来源、角色、指纹和模型特征可用性；
- `ReactionTemplateRegistry`：加载和校验版本化 Reaction SMARTS 模板；
- `RuleBasedDesigner`：执行骨架编辑和模板反应，输出产物及编辑审计；
- `ModelGuidedGraphSearch`：执行固定深度、固定 beam 宽度的受限搜索，并实施父骨架与指纹多样性限制；
- `MoleculeDesignEvaluator`：复用现有 `predict_with_model`、分子特征 workflow、适用域、可合成性和结构合理性过滤；
- `DesignTrace`：记录父结构、产物、模板、原子位点、键变化、设计深度、预测值、不确定度和过滤原因。

数据流：

```text
训练/候选有效骨架
    -> 规范化、角色标注、去重
    -> A 骨架编辑 + B Reaction SMARTS
    -> C 受限 beam 搜索（可选）
    -> RDKit 结构校验
    -> 分子特征 workflow
    -> 当前模型预测、适用域、不确定度
    -> 结构合理性/可合成性过滤
    -> 多样性筛选与配方结果
```

建议的主要接口：

```python
def design_molecules(

```

## 4. 模板与化学键连接规则

每个模板至少包含：

```json
{
  "template_id": "aryl_methyl_substitution",
  "version": 1,
  "roles": ["resin", "hardener"],
  "reaction_smarts": "...",
  "required_site": "aromatic_hydrogen",
  "bond_changes": [{"from": "site", "to": "substituent", "bond": "SINGLE"}],
  "allowed_elements": [1, 6, 7, 8, 9, 14, 15, 16, 17, 35, 53],
  "max_products": 32,
  "risk_level": "low"
}
```

编辑前约束：

- 骨架必须可被 RDKit 解析并通过基础结构检查；
- 只能选择明确可用的芳香氢、`-OH`、`-NH2` 或可扫描链段位点；
- 不编辑已带电原子、芳香键内部非氢位点或已达到最大价态的原子；
- 树脂和固化剂分别执行角色规则。

编辑后约束：

- 运行 RDKit sanitize；
- 校验元素白名单、键级、原子价态、孤立原子、重复连接和环闭合；
- 重新计算环氧、胺、羟基、酸酐、硫醇等官能团数量；
- 执行结构合理性和角色专用过滤；
- 不允许通过 0、NaN、基线值或插补值伪造缺失的分子特征。

## 5. 模型引导搜索与评分

C 每一轮执行：

1. 从当前 beam 中选择父结构；
2. 应用启用的 A/B 编辑模板；
3. 立即做廉价结构校验、规范化和去重；
4. 对唯一分子按当前 workflow 提取特征；
5. 调用当前模型，得到预测值和可用的不确定度；
6. 计算适用域、可合成性、结构合理性和新颖性；
7. 按模型族策略加权，保留 top-K 及少量探索候选；
8. 对父骨架、编辑类型和分子指纹实施多样性限制。

固定随机种子时，候选顺序、beam 结果和设计 hash 必须稳定。没有原生不确定度时，结果明确标记为代理不确定度，不伪装成模型原生输出。

## 6. 页面交互

“虚拟分子筛选”页面只保留新的“分子设计引擎”，删除旧的直接候选库、随机候选和独立预置分子入口。

页面分区：

1. **骨架来源与角色**：训练数据、当前有效候选或上传候选；树脂/固化剂角色；骨架上限；是否保留父结构。
2. **A 骨架编辑**：四类编辑开关、每类生成上限、每个骨架最大变体数。
3. **B 反应模板**：模板名称、SMARTS、位点要求、产物示例、风险等级和启用开关。
4. **C 模型引导搜索**：beam 宽度、搜索深度、每轮候选数、探索比例、相似度上限和随机种子。
5. **设计预览**：先运行少量骨架，展示父结构、产物、模板、连接位点、键变化、预测值、适用域、结构警告和失败原因。
6. **正式运行与结果**：显示设计进度、阶段漏斗、候选数量和失败统计；结果支持按预测提升、新颖结构和可合成性过滤并导出。

结果表至少包含：

`parent_smiles`, `product_smiles`, `component_role`, `design_method`, `reaction_template`, `edit_trace`, `design_depth`, `prediction`, `prediction_std`, `applicability_score`, `synth_score`, `chemical_validity`, `filter_reason`。

## 7. 错误处理与状态一致性

- 单个模板或位点失败：记录 RDKit/模板错误并继续其他分支；
- 单个骨架全部失败：保留审计记录，不中断整批任务；
- 所有骨架失败：阻止预测阶段并显示可操作原因；
- 生成数量不足：显示实际数量，不补随机分子；
- 模型特征契约不一致：直接停止，不静默填补；
- 修改设计参数后清除旧预览和旧结果，避免混用不同设计配置；
- 保存设计配置、模板版本、随机种子和 design hash，加载时重新校验。

## 8. 测试与验收

新增单元与集成测试：

1. 芳环、羟基、胺基和链段四类编辑均能生成合法连接；
2. 芳香位点、原子价态、键级和环结构错误会被拒绝；
3. 树脂/固化剂角色不会互换；
4. 模板或关键参数修改会改变 design hash；
5. 固定种子时 beam 搜索结果稳定；
6. 候选排序使用真实模型输出，不使用随机顺序；
7. 适用域、结构过滤或特征契约失败时阻止预测；
8. 设计轨迹、失败原因和父子结构保存/加载后一致；
9. 页面不再显示旧候选生成入口；
10. 现有模型导入、分子特征 workflow 和结果导出回归测试继续通过。

## 9. 非目标

首版不包含：

- 训练新的神经分子生成模型或下载外部生成模型权重；
- 无父结构的自由生成；
- 把树脂与固化剂错误地共价连接成单一分子；
- 修改现有分子特征提取算法、模型训练算法或适用域定义；
- 保留旧的随机候选/直接候选库流程作为页面入口。
