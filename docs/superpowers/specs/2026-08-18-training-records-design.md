# 训练记录与数据归档设计

## 目标

确保每次训练的完整输出都能在重启、切换启动目录和后续会话中读取，包括：

- 模型与推理所需的 pipeline、scaler、imputer；
- 完整的训练/测试特征矩阵和目标值；
- 有效特征列及目标列；
- 原始索引、数据切分策略、随机种子和训练参数；
- 分子特征流程、工艺特征流程、预测结果、交叉验证数据和图表。

同时提供可审计、可恢复的训练记录清理能力，避免误删完整实验数据。

## 现状与根因

当前 `TrainingRunManager` 使用相对路径 `results/training_runs`。Streamlit 从不同工作目录启动时，会创建或读取不同位置的记录目录。保存流程先写元数据，再分别写模型、表格和图像；模型保存异常会被吞掉，导致目录仍被展示为训练记录，但缺少可加载模型。旧记录也没有统一的文件清单，页面无法区分完整记录和部分记录。

## 方案

### 1. 稳定的记录根目录

记录根目录由项目根目录计算得到，而不是依赖当前进程工作目录。允许通过 `CFRP_TRAINING_RUNS_DIR` 覆盖，便于服务器部署和迁移。所有路径在读写前解析并限制在记录根目录内。

### 2. 训练记录包

每个 Run 使用独立目录，至少包含：

```text
metadata.json
manifest.json
model.pkl
model_<name>.joblib
feature_process.json
split_X_train.csv
split_X_test.csv
split_y_train.csv
split_y_test.csv
predictions_train.csv
predictions_test.csv
history.csv
training_curve.png
```

可选的交叉验证表格、响应图和额外图表继续以现有命名保存。矩阵和目标值写入 CSV，保留列名、行索引和 UTF-8 BOM；同时在元数据中记录行数、列数、数据类型摘要和源数据指纹。完整切分优先使用训练阶段实际使用的 `X_train/X_test/y_train/y_test`，不在记录页重新推断。

### 3. 清单与原子写入

保存先写入同级临时目录，完成全部必需文件后生成 `manifest.json`。清单记录：

- schema/version、run_id、创建时间；
- 每个文件的相对路径、字节数、SHA-256、文件类别和是否必需；
- `complete` 状态及缺失/失败原因。

临时目录只有在清单写入成功后才改名为正式 Run 目录。若模型或数据保存失败，记录标记为 `incomplete`，保存异常信息，不会被页面误认为可加载记录。对已有目录提供兼容扫描，不重写原始文件。

### 4. 读取与加载

`list_runs` 返回记录状态、缺失文件、总大小和可加载性，列表不再固定只显示最新 200 条；页面提供分页和筛选。`load_run` 先验证 run_id 和路径，再读取清单并校验必需文件。完整性错误只阻止依赖缺失文件的操作，例如模型加载；已有的元数据、历史表和预测表仍可查看。

加载模型前必须确认 `model.pkl` 或兼容的导出模型存在且校验通过。加载成功后同时恢复模型 artifact、有效特征列、训练/测试切分、目标值、流程配置和原始索引到 session state，优先用于 SHAP 和预测，避免依赖当前会话残留数据。

### 5. 清理中心

训练记录页增加清理面板，流程为：

1. 扫描记录并展示状态、大小、日期、模型和缺失项；
2. 提供筛选：完整/不完整、模型类型、时间范围、最小/最大大小、重复组；
3. 支持按选中项、保留最近 N 条、总容量上限和孤立临时目录生成候选；
4. 默认先移动到 `.training_run_trash/<timestamp>/`，写入清理日志和原路径；
5. 用户二次确认后执行，支持从回收目录恢复；永久删除作为单独的高级操作，并明确显示路径和大小。

重复记录只在内容指纹、模型类型、目标列和主要训练配置都一致时标记为候选，不自动删除最新记录。清理不会触碰 `models/`、`cache/`、当前加载模型或训练数据源。

## 错误处理

- 记录写入采用临时目录，进程中断不会产生“完成记录”；启动时扫描并显示残留临时目录。
- 单个可选图表失败不影响核心模型和数据保存，但会写入清单的可选文件错误。
- CSV 写入或模型序列化失败时，清单包含具体异常；页面显示可读的修复建议。
- 清单哈希不一致时禁止加载模型，允许查看文本和表格，并支持重新扫描。
- 旧记录缺少清单时自动生成只读诊断状态，不覆盖旧文件。

## 验证

新增单元测试覆盖：

- 从任意当前工作目录创建和读取记录仍指向同一项目目录；
- 保存完整切分数据后可原样恢复列名、索引和数据类型；
- 模型保存失败会产生不完整状态，不被标记为可加载；
- 文件大小或哈希变化会被检测；
- 清理扫描不会选择当前记录、完整记录或记录根目录外文件；
- 移入回收区后可恢复，清理日志包含原路径和操作时间；
- 旧版记录仍能浏览，缺失项可解释。

## 范围边界

本次不迁移已有 473 条记录的实际文件内容，不删除现有备份和缓存，也不改变模型训练算法。旧记录通过兼容扫描获得状态；新训练记录使用完整记录包格式。实现完成后再提供一次只读扫描报告，由用户决定是否执行清理。
