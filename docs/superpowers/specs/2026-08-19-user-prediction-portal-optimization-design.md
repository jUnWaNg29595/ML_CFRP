# CFRP 用户预测门户优化设计

## 1. 目标与边界

将现有独立的 `UserPrediction.py` 外部预测页面优化为主 CFRP 平台管理的用户门户：

- 主平台负责训练、验证、发布和回退模型。
- 用户门户只负责外部用户输入和预测结果展示。
- 外部用户不接触模型文件、训练配置、内部特征名、特征工程步骤或 SHAP 结果。
- 用户端保留单样品表单和 CSV/Excel 批量预测两种输入方式。
- 用户端继续以独立 Streamlit 服务运行在 `8555` 端口。

本次不将 `UserPrediction.py` 直接内嵌进主平台，也不由主平台自动启动或停止 `8555` 服务。

## 2. 当前问题

当前主平台和用户门户存在两套模型管理路径：主平台保存训练记录，用户门户再通过上传模型写入 `prediction_portal/managed_models`。这会造成模型来源、特征顺序和预处理流程脱节。

主要风险包括：

1. 用户门户主要依赖 `feature_cols`，没有强制复现完整分子特征流程。
2. `align_prediction_frame()` 会对缺失列自动补零或补 `NaN`，可能产生没有实际输入依据的预测。
3. 用户端可以选择多个模型，且可以看到内部特征配置，不符合外部用户定位。
4. 带有分子特征流程的模型目前只提示“尚未自动生成”，但仍可能继续预测。
5. 用户门户模型配置与主平台训练记录没有统一的发布、版本和回退机制。

## 3. 目标架构

### 3.1 主平台

主平台 `app.py` 负责：

- 读取训练记录和完整模型 artifact。
- 检查模型对象、目标列、特征顺序、预处理器和特征工程流程。
- 配置用户端中文名称、单位、输入说明和适用范围。
- 将通过检查的模型发布到用户门户。
- 管理模型版本、启用状态和回退。

### 3.2 发布清单

`prediction_portal/prediction_config.json` 保存用户门户需要的发布信息，而不是让外部用户上传任意模型。每个发布版本应包含：

- 材料方向和性能项。
- 用户端显示名称、单位和说明。
- 发布版本号、发布时间和发布状态。
- 模型 artifact 路径或受控引用。
- 训练指标和适用范围元数据。
- 模型特征顺序。
- 完整分子特征流程引用或配置。
- 缩放器、填补器和其他预处理契约状态。

### 3.3 用户门户

`UserPrediction.py` 只读取已发布且启用的版本，并提供：

- 材料方向选择。
- 性能项选择。
- 中文表单输入。
- CSV/Excel 批量上传。
- 输入校验报告。
- 预测结果和结果文件下载。

用户门户不提供模型上传、模型训练、模型多选、特征列覆盖、内部特征表或模型参数编辑。

## 4. 主平台入口开关

主平台侧边栏新增“用户预测门户”区域：

- 增加“启用门户入口”开关，默认关闭。
- 开启后显示 `http://localhost:8555` 入口。
- 使用新标签页链接打开用户门户。
- 检查 `8555` 端口状态并显示“可访问”或“未启动”。
- 未启动时提示运行 `启动预测平台.bat`。
- 不从 Streamlit 回调中创建后台进程，避免重复启动和服务生命周期失控。

该开关只控制主平台入口的可见性，不改变用户门户服务本身的启动方式。

## 5. 模型发布流程

管理员在主平台的训练记录或预测应用中执行：

1. 选择训练记录。
2. 查看模型、目标、特征数、特征流程和预处理器摘要。
3. 填写用户端名称、单位、输入说明和训练适用范围。
4. 执行发布前检查。
5. 检查通过后发布为用户门户版本。
6. 新版本成为当前稳定版本，旧版本保留并停用。
7. 必要时回退到上一个稳定版本。

发布前必须满足：

- 存在可用模型对象或完整 pipeline。
- 存在目标列和稳定的特征顺序。
- 分子模型存在可复现的特征流程。
- 缩放器、填补器等预处理器存在，或已由 pipeline 完整封装。
- 存在训练数据范围元数据。
- 用户输入映射可以从中文字段稳定转换到模型流程需要的原始输入。

缺少上述关键契约时，模型只能保存在训练记录中，不能发布为外部用户模型。

## 6. 用户端输入与预测流程

### 6.1 手动输入

- 用中文字段名、单位、说明、必填状态和示例值呈现。
- SMILES/BigSMILES 单独执行结构字段校验。
- 数值字段检查类型、缺失值和训练范围。
- 校验失败时禁止执行预测。

### 6.2 批量上传

- 接收 CSV、XLSX 和 XLS。
- 上传后先展示列匹配报告，不立即预测。
- 检查必需字段、重复字段、数据类型、空值和结构字段合法性。
- 将数据拆分为可预测行和问题行。
- 问题行不参与预测，并在结果中保留行号和具体原因。

### 6.3 统一执行

手动表单和批量表格都转换为统一的 `DataFrame`，再调用同一套预测服务：

1. 读取已发布模型 artifact。
2. 根据发布记录恢复原始输入到特征工程流程。
3. 按训练时顺序执行 BigSMILES/SMILES、分子特征、拼接、缺失值处理和缩放。
4. 按保存的特征顺序调用模型。
5. 返回预测值、输入校验状态和适用范围提示。

不再允许用“按列顺序猜测”或静默补零/补 `NaN` 作为缺失特征的默认策略。

## 7. 结果与错误处理

结果页显示：

- 中文性能名称、预测值和单位。
- 输入校验摘要。
- 是否超出训练数据范围。
- 超范围时显示“结果仅供参考”。
- CSV/Excel 下载，包含原始输入、预测值、状态和校验信息。

错误处理要求：

- 门户未启动：显示端口和启动命令。
- 模型文件不存在：版本自动标记不可用并提示管理员。
- 特征流程不完整：发布或预测前阻断，并指出缺少的契约项。
- 输入列不匹配：逐列展示缺失、冗余和类型错误。
- 批量预测中单行失败不影响其他合格行。
- 每次预测产生操作编号，便于定位问题。

## 8. 兼容与迁移策略

- 现有 `prediction_config.json` 保留，增加发布状态、版本和契约字段。
- 旧模型先标记为“待验证”，不自动对外开放。
- 具备完整 artifact 和特征流程的旧模型可以通过发布检查后继续使用。
- 缺少特征流程的旧模型不能用于需要分子特征复现的外部预测。
- 管理页面的模型上传能力迁移到主平台发布流程后，再从用户门户移除。

## 9. 验证要求

实现阶段至少覆盖：

- 发布检查拒绝缺少模型、特征顺序、预处理器或特征流程的 artifact。
- 发布版本能够正确写入和读取门户配置。
- 新版本发布、旧版本停用和回退行为正确。
- 表单和批量输入调用同一预测路径。
- 缺失列、重复列、错误类型、非法 SMILES 和超范围值被正确拦截。
- 已发布模型的多组分和分子特征流程顺序与训练配置一致。
- 主平台门户开关只影响入口可见性，不启动重复服务。
- `8555` 未监听和已监听两种状态显示正确。
