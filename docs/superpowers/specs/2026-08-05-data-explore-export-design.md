# 数据探索页面导出与预览增强设计

## 1. 背景

当前“数据探索”页面已经能够查看描述统计、相关性、分布和缺失值，但存在两个使用问题：

1. 图表虽然部分支持 CSV 或图片导出，导出入口和格式不统一，难以保存图表背后的绘图数据，也不便于批量导出。
2. 数据预览默认只显示少量列，数据集包含大量分子、工艺和派生特征时，用户无法快速选择真正关心的特征组合。

本次改动只针对数据探索页面，不改变数据清洗、特征工程、模型训练和虚拟筛选逻辑。

## 2. 目标

- 为数据探索页的图表提供统一的“图表数据 + 图表文件”导出能力。
- 支持导出当前处理数据和原始数据；默认使用当前处理/清洗后的数据。
- 保留各分析标签页的就地快速导出，同时增加统一导出中心。
- 将数据预览改为可搜索、多选的特征列选择，并允许调整预览行数。
- 对大数据集保持界面可用，避免默认渲染全部列或全部行。
- 导出文件使用稳定、可追溯的文件名，并包含必要的分析上下文。

## 3. 非目标

- 不重写现有数据清洗和统计计算逻辑。
- 不改变当前页面默认使用 `processed_data` 的优先级。
- 不自动修改用户的数据类型、缺失值或特征选择结果。
- 不把所有分析图表强制合并为一个大型报告文件。

## 4. 用户交互设计

### 4.1 数据预览

在数据探索页增加“数据预览”区域：

- 数据源显示：
  - `当前处理数据`：优先使用 `processed_data`，否则使用 `data`。
  - 如果原始数据存在，允许切换查看 `原始数据`。
- `预览行数`：
  - 默认 50；
  - 最小 5；
  - 最大值根据数据行数动态确定，至少允许到 5000；
  - 使用 `head(n)`，不改变底层数据。
- `预览特征/列`：
  - 可搜索多选；
  - 默认选择当前数据的前 8 列，兼容现有页面行为；
  - 提供“全选当前筛选结果”和“清空选择”；
  - 清空时明确提示，而不是隐式渲染全部列；
  - 显示已选列数量；
  - 按用户选择顺序显示列。
- 预览表格只渲染用户选择的列和行，不限制底层数据列数。

### 4.2 快速导出

每个能够生成图表的分析区域，在图表下方提供统一的快速导出控件：

- `导出图表数据`：
  - CSV；
  - Excel（若当前环境可用，使用现有 Excel 导出依赖；不可用时给出明确提示）。
- `导出图表`：
  - PNG；
  - SVG；
  - HTML（交互式 Plotly 图表优先）。

快速导出默认导出当前分析实际使用的数据，而不是未经处理的原始数据。导出文件名包含：

- 页面/分析名称；
- 数据源标识；
- 时间或稳定短标识（避免同名覆盖）。

### 4.3 统一导出中心

在“导出”标签页中增加“图表与数据导出中心”，提供：

1. 数据源选择：
   - `当前处理数据`；
   - `原始数据`；
   - 默认 `当前处理数据`。
2. 分析类型选择：
   - 描述统计；
   - 相关性矩阵；
   - 分布图；
   - 缺失值；
   - 当前页面已经生成且可导出的其他分析结果。
3. 导出内容选择：
   - 仅图表数据；
   - 仅图表文件；
   - 两者都导出。
4. 文件格式选择：
   - 数据：CSV、Excel；
   - 图表：PNG、SVG、HTML。
5. 字段选择：
   - 对需要字段选择的分析复用统一的可搜索多选控件；
   - 未选择足够字段时禁用相关分析并显示原因。

统一导出中心支持单文件下载。对于同一次导出的多个文件，生成 ZIP 包；ZIP 内保留清晰的目录和文件名。

## 5. 数据与实现约定

### 5.1 数据源

定义两个显式数据源：

- `processed`：`st.session_state.processed_data`，存在且为非空 DataFrame 时优先使用；
- `raw`：`st.session_state.data`。

页面当前分析默认使用 `processed`，没有处理数据时回退到 `raw`。导出中心的选择必须在生成图表和导出数据时同时生效，不能只改变表格而不改变图表。

### 5.2 图表导出适配

新增一个小型导出适配层，根据图表对象类型分发：

- Plotly Figure：
  - HTML 使用 Plotly 自带导出；
  - PNG/SVG 使用 Plotly 图像导出能力；
- Matplotlib Figure：
  - PNG/SVG 使用 `savefig`；
  - HTML 使用包含图片和元数据的轻量 HTML 包装，不能要求用户安装额外浏览器组件。

图表导出失败不能阻断数据探索页面；应在对应控件附近显示具体缺失依赖或格式原因。

### 5.3 数据导出

- CSV 使用 UTF-8 with BOM，保证中文列名在 Windows Excel 中可读；
- Excel 使用内存缓冲区生成，不落地临时文件；
- 导出前保留列顺序、索引策略和缺失值，不进行额外插补；
- 导出数据增加必要的元信息工作表时，不能覆盖原始列名；元信息至少包含数据源、行数、列数和分析名称。

### 5.4 会话状态

预览列、预览行数、数据源和导出中心选择使用独立且稳定的 session state key，避免与数据清洗、模型训练和其他页面控件冲突。

当数据集或列集合变化时：

- 自动移除已经不存在的列；
- 保留仍然存在的用户选择；
- 若最终没有选中列，显示提示并不渲染全表。

## 6. 验收标准

### 6.1 预览

- 能搜索并选择任意存在的列；
- 能选择超过默认 8 列；
- 能调整预览行数，至少能查看 5000 行（受数据实际行数限制）；
- 切换原始/处理数据后，列选择会安全同步；
- 空选择不会导致异常或误显示全部列。

### 6.2 图表导出

- 相关性、分布、缺失值等现有图表均有统一导出入口；
- Plotly 图表可导出 CSV/Excel 与 HTML；
- 可用依赖存在时，Plotly/Matplotlib 图表可导出 PNG/SVG；
- 任一格式失败只提示当前格式，不影响其他导出；
- 导出的数据与图表实际使用的数据源一致。

### 6.3 导出中心

- 默认数据源为当前处理数据；
- 可以切换为原始数据；
- 可以选择分析类型和导出格式；
- 多文件导出时生成 ZIP，文件名和目录清晰；
- 页面重新渲染后不会丢失用户选择。

### 6.4 回归

- 不影响数据上传、清洗、特征选择、模型训练和虚拟筛选；
- 不引入强制性的额外运行时服务；
- 对空数据、单列数据、无数值列和无缺失值数据有明确提示。

## 7. 推荐实施顺序

1. 抽取数据源解析、预览选择和导出格式转换的纯函数。
2. 先完成预览控件和数据导出。
3. 为 Plotly/Matplotlib 增加统一图表导出适配。
4. 在各图表旁接入快速导出。
5. 在导出标签页加入统一导出中心和 ZIP 打包。
6. 添加纯函数测试和页面级最小回归检查。

## 8. Task 4 实际实现差异

- 导出中心在“💾 导出”标签中一次性生成 ZIP，仍复用现有数据源解析、数据格式转换和图表格式适配函数。
- 描述统计没有独立图表对象，因此选择“图表文件”时仅跳过图表文件，选择“图表数据”时仍导出统计数据。
- Excel 依赖 `openpyxl`；Plotly 的 PNG/SVG 依赖 `kaleido`。依赖缺失时仅提示对应内容并继续生成其他文件。
- 当前导出中心使用页面已有的默认图表列集合；未新增后台线程、临时文件或常驻服务。
